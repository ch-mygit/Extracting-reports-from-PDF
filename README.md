# מערכת לעיבוד וגנרוט דינמי של דוחות נוכחות סרוקים (Attendance Pipeline)

מערכת מודולרית, מסווגת ופולימורפית ב-Python המיועדת לקליטה, פיענוח (OCR), סיווג, טרנספורמציה דטרמיניסטית וייצור מחדש של דוחות נוכחות חודשיים סרוקים בקבצי PDF (מסוג A ומסוג B).

## מטרת המערכת

המערכת פותחה במטרה לעבד דוחות נוכחות סרוקים (באיכות סריקה משתנה ובשפה העברית), לחלץ מתוכם את הנתונים העסקיים למודל נתונים מובנה ומאומת (Typed Dataclass), לבצע מניפולציות וחישובים מחדש באופן דטרמיניסטי (כגון צמצום מספר השורות, יצירת שעות כניסה ויציאה חדשות וחישוב מדרגות שכר ושעות נוספות מאפס), ולייצר קובץ PDF חדש, דינמי ואיכותי הנאמן ב-100% לפורמט של כל סוג דוח, ללא שינוי קובץ המקור.

## ארכיטקטורה ותבניות עיצוב (Design Patterns)

המערכת בנויה לפי עקרונות SOLID והפרדת רשויות מלאה:

1. **Facade Pattern (`main.py` -> `AttendancePipelineFacade`)**:
   מנהל את כל שלבי הצינור מקצה לקצה בממשק פשוט ויחיד (`process_pdf`), תוך שמירה על קוד אגנוסטי לחלוטין לסוג הדוח.
2. **Factory Method Pattern (`ReportPipelineFactory`)**:
   מבודד את כל הידע הספציפי על סוגי הדוחות (Type A מול Type B). לאחר שהמסווג מזהה את סוג הדוח, המפעל מחזיר אובייקט רכיבים אחיד (`PipelineComponents`) הכולל את ה-Parser, ה-Strategy והתבנית הרלוונטית. **אין תנאי `if type == 'A'` מפוזרים בקוד העיבוד.**
3. **Strategy Pattern (`src/strategies/`)**:
   כללי הטרנספורמציה והחישוב ממומשים תחת ממשק מופשט אחיד (`BaseTransformationStrategy`), המאפשר להחליף אלגוריתמי טרנספורמציה בקלות.
4. **Strongly Typed Models (`src/models/`)**:
   כלל ברזל: תאריכים ושעות נשמרים אך ורק כאובייקטים ייעודיים (`datetime.date`, `datetime.time`, `datetime.timedelta`) או כמספרים (`float`), ולעולם לא כמחרוזות (`str`).

## דרישות קדם (Prerequisites)

לפני הרצת המערכת יש לוודא שהכלים הבאים מותקנים במחשב:

1. **Python 3.10 ומעלה**.
2. **Tesseract OCR (כולל חבילת עברית)**:
   * התקנה ב-Windows: מומלץ להוריד את המתקין מ-[UB-Mannheim Tesseract](https://github.com/UB-Mannheim/tesseract/wiki).
   * **חובה לסמן במהלך ההתקנה את התמיכה בשפה העברית (Additional script data -> Hebrew, Additional language data -> Hebrew).**
   * נתיב ההתקנה הסטנדרטי מזוהה אוטומטית: `C:\Program Files\Tesseract-OCR\tesseract.exe`.
3. **Poppler (להמרת עמודי PDF לתמונות)**:
   * התקנה קלה דרך Windows Package Manager:
     ```powershell
     winget install osdn.poppler
     ```
   * המערכת כוללת מנגנון זיהוי אוטומטי של בינארי Poppler ב-Windows.

## הוראות הרצה ובדיקה מפורטות

המערכת מאפשרת קליטה ישירה משם קובץ (חיפוש אוטומטי בתיקיית `data/input/`) או מנתיב מלא. כל תוצרי הריצה נשמרים בתיקיית `data/output/`.

### 1. הרצת בדיקות מקדימות (Unit Tests & Diagnostics):
```powershell
# הרצת כל חבילת הבדיקות האוטומטיות (16 בדיקות מלאות עם Pytest):
python -m pytest tests -v

# או הרצת בדיקות יחידה בנפרד:
python tests/test_environment.py   # בדיקת סביבה, ספריות ומנועי OCR
python tests/test_models.py        # בדיקת מודל הנתונים וכלל הברזל
python tests/test_rules.py         # בדיקת טרנספורמציות, הפרדת שבת ו-150%, ושורות חג
```

### 2. הרצת הצינור המלא (Pipeline) על דוח מסוג A:
```powershell
python main.py a_r_9.pdf
```
(ניתן גם לציין נתיב מלא: `python main.py data/input/a_r_9.pdf`)

לפתיחה וצפייה בתוצאה המופקת:
```powershell
Start-Process "data/output/output_a_r_9_verified.pdf"
```

### 3. הרצת הצינור המלא על דוח מסוג B:
```powershell
python main.py n_r_5_n.pdf
```
או על קובץ נוסף:
```powershell
python main.py n_r_10_n.pdf
```

לפתיחה וצפייה בתוצאה המופקת:
```powershell
Start-Process "data/output/output_n_r_5_n_verified.pdf"
```

### 4. הרצה עם כמות שורות מותאמת אישית או נתיב פלט מותאם:
כברירת מחדל, המערכת מייצרת **כמות שורות רנדומלית** דינמית מתוך קובץ המקור. ניתן לקבוע כמות שורות מדויקת באמצעות הדגל `--rows` (או `-r`):
```powershell
# הרצה רגילה (ברירת מחדל: כמות שורות רנדומלית):
python main.py a_r_9.pdf

# הגדרת כמות שורות מפורשת (למשל: 8 שורות):
python main.py a_r_9.pdf --rows 8

# הרצה עם נתיב פלט מותאם אישית:
python main.py a_r_9.pdf -o "data/output/custom_report.pdf"
```

### 5. ייצור קובץ PDF חדש לחלוטין מאפס (ללא צורך בקובץ סריקה קיים או OCR):
המערכת כוללת מנוע ייצור סינתטי (`SyntheticReportGenerator`) המאפשר לחולל דוחות חדשים לחלוטין בפורמט A או B עם נתונים ריאליסטיים תקניים:

* **ייצור דוח חדש בפורמט A דרך main.py:**
  ```powershell
  python main.py --new A
  ```
* **ייצור דוח חדש בפורמט B:**
  ```powershell
  python main.py --new B
  ```
* **ייצור דוח מותאם אישית עם שם עובד, תאריך ושם קובץ:**
  ```powershell
  python main.py --new A --name "דנה כהן" --month 10 --year 2022 -o "data/output/dana_report_a.pdf"
  ```
* **או באמצעות כלי הייצור הייעודי `generate_report.py`:**
  ```powershell
  python generate_report.py --type A --name "ישראל ישראלי" --month 1 --year 2023
  ```

לפתיחת הקובץ שנוצר:
```powershell
Start-Process "data/output/new_report_A.pdf"
```

## יומן החלטות ארכיטקטוניות (ADR)

### נושא: שימוש במנוע תבניות דינמי (HTML/Jinja2 ל-PDF) לעומת עריכה ישירה על קובץ המקור (PDF Redaction / In-Place Editing)

**סטטוס:** התקבל (Accepted).

**הקשר (Context):**
בשלב ייצור ה-PDF החדש, נדרשנו לקחת את נתוני הדוח המקורי שעברו טרנספורמציה (צמצום מספר השורות לכמות דינמית ורנדומלית, שינוי זמני כניסה ויציאה וחישוב מחדש של כל הסיכומים) ולייצר מסמך PDF סופי. עלתה השאלה האם לערוך ישירות את קובץ ה-PDF המקורי ע"י מחיקה/כיסוי (Redaction) והדבקת טקסט חדש במיקומים הישנים, או לבנות מסמך דינמי חדש מאפס באמצעות מנוע תבניות HTML/CSS (Jinja2) והמרה ל-PDF.

**ההחלטה (Decision):**
בחרנו באופן חד-משמעי בגישת **בנייה דינמית מאפס באמצעות Jinja2 (HTML/CSS) והמרה ל-PDF**, ופסלנו עריכה ישירה (Redaction) של ה-PDF המקורי.

**הנימוקים והרציונל הארכיטקטוני:**
1. **טבלאות דינמיות וכיווץ שורות (Dynamic Shrinking & Flow):**
   דרישת הליבה הייתה לצמצם את כמות השורות לכמות רנדומלית דינמית. בעריכה ישירה של PDF (Redaction), המסמך המקורי קשיח – מחיקת שורות מותירה "חור" ריק ענק באמצע העמוד, ושורות הסיכום נשארות תקועות בתחתית הדף במרחק עצום מהטבלה. מנוע תבניות HTML מנהל Document Flow טבעי: הטבלה מתכווצת במדויק לגודל כמות השורות הנבחרת, ואזור הסיכומים זז וצמוד אליה באופן דינמי ואלגנטי.
2. **טבעם של קבצים סרוקים (Raster Scans vs. Vector PDFs):**
   קבצי הקלט הם דוחות סרוקים המורכבים מתמונת ביטמפ (Raster Image) ולא מטקסט וקטורי חי. ניסיון לבצע Redaction על תמונה סרוקה דורש צביעת מלבנים לבנים מעל פיקסלים קיימים והדבקת טקסט וקטורי מעליהם, מה שמייצר מסמך "טלאים" שנראה פגום ומזויף. יצירת מסמך וקטורי חדש מייצרת PDF איכותי, חד, קריא וברמת גימור מקצועית.
3. **הפרדת רשויות ותמיכה פולימורפית (Separation of Concerns & Polymorphism):**
   עריכת PDF ישירה קושרת את לוגיקת העיבוד לקואורדינטות (X, Y) קשיחות של מסמך מסוים. לעומת זאת, מנוע תבניות מפריד לחלוטין בין מודל הנתונים (`AttendanceReport`) לבין שכבת התצוגה (`type_a_report.html` מול `type_b_report.html`). כל סוג דוח מקבל תבנית ייעודית ומדויקת למבנהו (למשל: סוג B כולל טבלת סיכום עליונה ושבתות מוצללות, בעוד סוג A כולל עמודות 100%/125%/150%/שבת וטבלת סיכום תחתונה).
4. **טיפול מושלם בכיווניות עברית (Native BiDi & RTL):**
   ספריות עריכת PDF מסורתיות בפייתון סובלות מקשיים כבדים בהיפוך אותיות, טיפול במספרים מעורבים בעברית ויישור עמודות מימין לשמאל. שימוש ב-HTML/CSS תקני עם `dir="rtl"` ופונטים עבריים מבטיח רינדור מושלם של טקסט מעורב עברית-אנגלית-מספרים ללא צורך במניפולציות BiDi מורכבות.
